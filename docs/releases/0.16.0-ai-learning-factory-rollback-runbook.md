# Nyra/Core 0.16 rollback runbook

This runbook disables or reverts `0.16.0-ai-learning-factory` without deleting
dataset metadata, telemetry, audit entries or work capsules. It does not change
OAuth, secrets, databases, domains or scaling.

## Preconditions

1. Confirm tenant `codexai`, the affected service and the exact live deploy ID.
2. Open a Core rollback gate bound to the failed deploy, the healthy rollback
   deploy and this runbook.
3. Capture health, readiness, failing smoke evidence and the current feature
   flags without printing environment values that contain secrets.
4. Stop if the healthy rollback point does not match
   `0.16.0-ai-learning-factory-rollback-point.json`.

## Fast feature rollback

Set only the following non-secret flags on Universal Core:

```text
NYRA_AI_LEARNING_FACTORY_MODE=off
NYRA_AGENTIC_EFFICIENCY_MODE=off
CORE_AGENTIC_BUDGET_MODE=observe
AGENTIC_HARD_BUDGET_STOP=false
```

Do not change `GOVERNED_AGENT_DATABASE_URL` or any existing database binding.
Wait for the platform-managed restart, then verify health/readiness, the
13-tool MCP surface and absence of autonomous execution.

## Code rollback

If disabling the flags is insufficient, redeploy the exact healthy deploys from
the rollback-point artifact:

- Universal Core: `dep-d9jnlb43plds73e2vep0`
- Core MCP: `dep-d9jnlb1q7b2c73cve46g`

Do not redeploy Nyra Core unless its code was modified by the release. Never use
a force-push.

## Database rollback rehearsal

The down migration records the v0.16 state as `disabled` and preserves all
tables and audit history. The rehearsal must:

1. apply the additive up migrations to an ephemeral PostgreSQL instance;
2. create tenant-scoped test records and restart the runtime;
3. apply the down migrations;
4. confirm audit, telemetry and work-capsule metadata remain present;
5. confirm v0.16 writes are rejected while disabled;
6. reapply the up migrations and confirm idempotent recovery.

Never run destructive table, schema, role or database deletion as part of this
release rollback.

## Post-rollback smoke

- Universal Core and Core MCP health/readiness are green.
- `execution_enabled=false`.
- MCP advertises exactly 13 top-level tools.
- ChatGPT cannot discover, select or force a vertical branch.
- Adjacent software cannot cross its client/audience boundary.
- No provider execution or external action occurred.
- The audit contains the rollback action, Core receipt and rollback reference.
